# Bruin 生产化审查与六轮迭代

本审查针对当前代码和模拟服务端测试，不等同于完整的生产安全审计。pi 的官方文档采用按需发现 Skill 的方式；Bruin 保留按需加载，并提供四个自有的基础 Skill。没有复制 pi 的 Skill 内容。

## 第一轮：模型目录与会话选择

**发现**：桌面选择器只列出 `config.json` 的模型别名；同一个 API 返回的其他模型无法选择。编辑别名配置时还会覆盖已有会话独立选定的模型。

**修改**：增加四类 Provider 的模型目录请求；桌面会话提供模型 ID 下拉框及刷新入口。模型切换写入 SQLite 会话快照和 `model_switched` 事件。编辑默认配置时保留同一 Provider、同一 Base URL 下的会话模型覆盖值。

**验证**：本地模拟 OpenAI 兼容、Anthropic 和 Google 模型列表，检查认证头、分页、去重、会话切换和配置编辑后的保留行为。

## 第二轮：桌面图标与基础 Skill

**发现**：旧图标是字母 B，开发态 Dock 可能显示默认 Electron 图标；用户无法切换背景色。Skill 注册表只扫描用户数据目录，新用户没有可用的基础 Skill。

**修改**：绘制纯白背景熊头 SVG；构建时生成五色 PNG，macOS 打包生成 `icon.icns`。运行时图标配色保存在 `BRUIN_HOME/appearance.json`，可在外观界面切换。增加 `plan`、`debug`、`code-review`、`test` 四个只读内置 Skill，默认启用、按需读取；独立保存启停状态，用户 Skill 继续走原安装机制。

**验证**：检查生成图像、macOS 包内 `CFBundleIconFile`、图标资源和打包后的 Skill 文件；测试内置 Skill 的发现、加载、停用及禁止卸载。

## 第三轮：错误与事件边界

**发现**：重复选择相同模型会写多余的模型切换事件。模型目录的底层网络异常可能暴露连接细节；跟随重定向会有转发凭据的风险。模型调用错误若包含 API Key，原代码会写入事件日志并显示在界面。

**修改**：相同会话配置不再写切换事件；模型目录禁用重定向、限制超时和响应大小并统一网络错误；模型调用错误在持久化和上报前脱敏当前 API Key。

**验证**：模拟重定向确认密钥没有转发；模拟含密钥的模型错误确认显示与事件均不含该值；检查重复选择不增加事件。

## 第四轮：MCP 与权限边界

**发现**：原模型网关只有固定六个工具，无法发现或调用 MCP 服务器；简单把 MCP 工具塞进执行器会让服务器进程继承不必要的模型密钥。

**修改**：接入官方 TypeScript MCP 客户端，支持 stdio 和 Streamable HTTP；在配置中只保存命令、URL、环境变量名；stdio 仅继承基础运行环境和显式列出的变量。模型经 `mcp_list_tools` 发现，再以 `mcp_call` 调用，后者每次审批并写入会话事件。CLI 与只读子 Agent 使用缩小的工具集。

**验证**：本地模拟 MCP stdio 服务器完成握手、工具列表和调用；断言未继承未授权的测试密钥。类型检查与桌面构建通过。

## 第五轮：编排、隔离和中断

**发现**：只有同步 Agent 回合；无法在独立 Git 工作树里研究，也无法追踪后台命令。关闭应用时若直接关闭数据库，异步任务仍可能尝试追加结果。

**修改**：增加最多两个并发的只读子 Agent、最多两个并发的沙箱后台 Shell、Git 工作树创建/列出/安全移除、静态 Hook。子 Agent 与后台任务在父会话留下开始和结束事件，进程关闭时取消并等待任务结算。工作树移除不使用 `--force`；Hook 复用 Shell 沙箱。

**验证**：临时 Git 仓库创建并移除工作树；模拟执行器验证 Hook、后台任务与子 Agent 的事件及状态。桌面入口完成打包检查。

## 第六轮：规划、界面与历史数据

**发现**：缺少“先计划、后批准”的执行门禁。原界面默认暗色；历史版本写入的模型错误可能在会话界面显示旧密钥。

**修改**：会话级规划模式保存在事件日志；批准前拒绝有副作用的工具，计划修订会撤销批准；执行步骤可更新状态。界面默认纯白并可切换黑色，主题独立于熊图标背景色。桌面后台在返回历史事件时对已知密钥模式脱敏；新模型错误仍在持久化前脱敏。

**验证**：单元测试确认未批准的计划阻止文件写入、批准和进度事件可恢复；遗留事件的桌面读取脱敏有回归测试。实际启动 macOS 应用，确认纯白主题与新入口可见。

**打包复核**：ZIP 完整性检查后发现独立 Node 运行时缺少生产依赖；已显式把 `.desktop-runtime/node_modules` 复制进应用资源。使用包内 Node 和后台脚本执行 `bootstrap`，确认 SQLite、MCP 包与四个内置 Skill 可加载。

## 当前生产边界（2026-09-29）

上述六轮是历史迭代记录。后续已增加跨进程会话租约、可自定义的模型上下文窗口与保守输入预算、Docker Shell 的取消清理，以及 macOS/Linux/Windows 构建矩阵。单用户可信开发机可按 `README.md` 和 `SECURITY.md` 中的边界使用。

仍需验证或补齐：

1. **跨平台运行**：CI 已配置三平台测试与打包，但 Windows/Linux 的实际桌面启动、文件工具和 Docker 沙箱仍需目标机器验收。
2. **本地文件竞态**：写入前复核路径与文件身份；其他本地进程并发替换路径时仍可能有检查到写入之间的竞态。用户已选择保留本地文件工具，适用可信开发机。
3. **公开分发**：macOS 尚未签名、公证；Windows/Linux 发布包及自动更新也没有完成发布验收。
4. **外部能力**：真实 Provider 的模型与工具兼容性需凭目标账号验证；MCP stdio 隔离取决于宿主沙箱能力。OAuth 交互登录已提供，凭证仅存后台内存，真实授权服务器和系统浏览器端到端仍待验证。
5. **长期运行**：崩溃或强杀后可能留下 Docker 容器；后台 Shell 和子 Agent 不自动续跑。上下文预算是 UTF-8 字节估算，不是模型 tokenizer 的精确计数。

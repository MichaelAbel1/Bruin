# Bruin 改进实施清单

**下一项从 03 开始。** 先修 CLI 空跑、偏好串项目、长输入丢验收条件，再做记忆召回、完成验证和多 Agent 集成。每个编号可以单独建 issue 或 PR。勾选表示在本次工作树已验证，未勾选表示仍有交付物。问题的原始复现和 Claude Code 官方资料见[对照评估](CLAUDE_CODE_GAP_ANALYSIS.md)。

基线为 2026-11-19，Bruin 0.12.1，HEAD `9c5c35a` 加当时未提交的改动。以下默认面向本机个人开发者。P0 是可能损失用户工作或跨越授权边界的问题，P1 是日常正确性、交付或恢复问题，P2 是效率与集成改进，P3 由用户群和测量结果决定。**阶段给出建议顺序，前置编号才是实施依赖。** 未标前置的任务可独立进行。

| 阶段                         | 交付结果                                              | 何时进入下一阶段                                                               |
| ---------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------ |
| 一 · 正确性与基线（01–06）   | 用户修改、项目边界和关键约束受保护，CI 能收到真实输入 | 01–05 的失败场景有回归；06 有两题可重复的试跑基线                              |
| 二 · 日常开发（07–14）       | 续跑能找回记忆，验证有证据，多文件改动可预览和恢复    | 一次涉及三个文件的改动能从“继续”走到验证、审核及冲突处理                       |
| 三 · 多 Agent（15–21）       | 两份子任务成果能导出、纠偏、集成，预算可解释          | 两个子任务的成果经联合测试，故障、取消或预算耗尽后均能说清每份成果的位置和状态 |
| 四 · 效率与产品入口（22–29） | 在相同任务上衡量推理、检索、长会话与 IDE/CLI 体验     | 目标使用场景有对照数据后，再选择优化项或发布平台                               |
| 五 · 按需求扩展（30–32）     | 可复用角色、更多并发、公开分发                        | 各项独立立项，使用下列触发条件决定投入                                         |

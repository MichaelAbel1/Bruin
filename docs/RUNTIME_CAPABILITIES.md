# Bruin 桌面 Agent 扩展能力

本页描述 MCP、子 Agent、Git 工作树、后台任务、Hook 和规划模式。桌面从 Electron 主窗口经 `desktop-host.ts` 进入 `AgentRunner`，CLI chat 与 ACP 也使用完整工具网关和同一运行时服务；状态写入 SQLite 会话事件。只读子 Agent 使用缩小的工具集。独立调度入口见 [本机后台服务](SERVICE.md)，各入口差异和动态能力清单见 [运维与诊断](OPERATIONS.md)。

## 工作区记忆检索

每次模型调用前，工作区记忆按当前任务的关键词和已成功访问的文件路径排序。常见的「继续」「按上面改」短句会沿用最近的任务描述；新的任务描述或工作区切换会重置旧线索。匹配项提供正文摘录，每页最多 2000 字符；其余条目只显示 key 和更新时间。自动注入总计最多 8000 字符，完整内容可通过 `list_memory` 读取。记忆仅作为本工作区的参考资料。

桌面端可从会话顶部的「整理会话记忆」选择本工作区内已结束的回合，再点击「生成候选」。Bruin 使用会话配置的模型处理有限的用户消息、Shell 命令及其退出状态和相关旧笔记，对已知密钥和常见凭据格式做脱敏。预览展示候选正文、旧笔记和作为依据的会话事件。逐条确认后才写入工作区记忆，保存时记录来源。若旧笔记在预览后已更新，需要重新生成候选。

## 会话用量

桌面对话顶部显示当前会话中已记录模型响应的输入/输出 Token 累计，展开后可查看用量数据的覆盖情况。缺少供应商用量时显示“未提供”，仅部分响应有数据时使用 `≥` 标识；合法的 0 保留为 0。统计从原始会话事件重建，压缩历史和切换模型不会清零，不需要更改数据库结构。

这不是当前上下文占用或费用账单，不包含上下文摘要、失败/中断请求和其他会话（包括子 Agent）的用量；尚未提供金额估算或费用上限。

## 仓库探索工具

CLI、桌面 Agent 和只读子 Agent 都可使用：

- `read_file({ path })`：保持原有全文预览行为，输出仍受字节上限限制。
- `read_file({ path, startLine, lineCount })`：按 LF 分行，保留原始 CRLF；起始行从 1 开始（最多 1,000,000），行数最多 10,000。指定任一分页参数时，起始行默认 1、行数默认 200。返回行范围与下一页起始行；超长单行被字节上限截断时明确提示该行未完整输出，不将其当作完整页。每次从文件开头扫描，不持久保存索引，受读取超时限制。
- `list_files({ path?, offset?, limit? })`：复用桌面目录浏览器的路径校验和排序逻辑，一次浏览一个目录，默认工作区根目录、偏移 0、100 条，最多 300 条。返回 JSON `entries`（含 `name/path/kind`）、`hasMore` 和 `nextOffset`；字节预算不足时减少条目并调整下一页偏移，预算无法容纳一个条目时明确报错。跳过符号链接和特殊文件，包含隐藏文件，不应用 gitignore。目录在页间变化时可能影响偏移结果，不提供快照一致性。

两项工具均可在未批准计划阶段使用，不新增写入能力，也不能浏览工作区外或符号链接指向的路径。工具可读不意味着模型已经完整读取文件；应结合分页或截断标记判断。

索引、文件快照回滚与 MCP OAuth 的使用方法和限制见 [仓库索引、文件回滚与 MCP OAuth](REPOSITORY_RECOVERY_AUTH.md)。

## MCP

在侧边栏「MCP 与自动化」中添加服务器。支持两种传输：

- **stdio**：填写可执行命令、每行一个参数，以及显式允许传给服务器的环境变量名。Bruin 启动独立 MCP 进程，默认只传 `PATH`、`HOME`、`TMPDIR`、`LANG`，不继承模型密钥。服务器进程由 MCP SDK 管理，不等同于 Bruin 的受限文件工具进程或 Shell 沙箱。只安装和启动可信服务器。
- **Streamable HTTP**：填写 URL 和可选 Bearer Token 环境变量名。远端地址必须使用 HTTPS，本机 loopback 可用 HTTP。Token 值只从进程环境读取，不写入配置文件。

「测试工具」执行握手及 `tools/list`。模型通过 `mcp_list_tools(server)` 发现工具，再以 `mcp_call(server, tool, arguments)` 调用。**每次 MCP 调用都需审批**，参数与结果记录在事件日志。连接、列表与调用分别有 10 秒、10 秒、30 秒超时；单条 stdio 消息限制为 1 MB，返回给模型的调用结果限制为 100 KB。远程服务仍可能产生外部副作用，超时或断线后的结果可能不确定；Bruin 会标记 `tool_unknown`，不会自动重试。

同名服务器的连接、列表、调用和断开操作按顺序完成，避免切换工作区或关闭连接时中断另一项请求；不同服务器保持独立。同一服务器的慢请求会延迟后续操作，仍受各请求超时限制。工具列表分页由当前 SDK 自动处理，Bruin 复用它的实现。

## 子 Agent

子 Agent 完成时将最后回答的最多 20,000 字符写入父会话完成事件。CLI、桌面与 ACP 的主 Agent 在结束当前回合前等待在途子 Agent，并自动读取结果或失败原因进行汇总，无需反复查询状态；结果属于不可信任务资料，不代表新的用户指令或授权。等待可取消，并计入本轮时间预算；达到调用或时间预算仍暂停。历史完成事件可用于恢复后汇总，但不会自动重跑子任务。此流程保留当前主回合，桌面仍可排队发送后续消息。

子任务结果首次写回失败后，Bruin 会在父子租约仍有效时用同一结果重试一次。已有完成记录时复用该记录。仍无法保存时，本次等待会先让其他在途子任务结算，再报告错误。取消、预算上限和「立即调整」仍可提前结束等待。

主 Agent 优先接收最新的子任务结果。上下文越小，回答、错误和路径的预览越短。预览保留任务 ID 并标记文本截断，空间不足时优先省略较早的记录。可用 `subagent_status` 查看持久结果。子任务暂停或失败时，父会话也会保存原回合已产生的部分回答。旧记录缺少回答时，状态查询只从原始子任务回合取回内容。

桌面「立即调整」消息在持久入队后唤醒主 Agent 的子任务等待，使主 Agent 可以读取新要求、调整方向或调用 `cancel_subagent`；不会自动替用户取消所有子任务。「排队跟进」仍等待子任务结束并由主 Agent 汇总后再处理。调用预算用尽时，已经接收的新要求保留在用户事件中并暂停，下一次继续时不会重复投递或跳过该消息。唤醒通知仅在当前后台进程内使用，SQLite 事件仍是消息队列的持久依据。

模型或桌面界面可启动子 Agent，最多同时两个，正在创建工作树的任务也占用名额。默认 `spawn_subagent({ prompt })` 保持只读，只暴露 `read_file`、`list_files`、`search_repository`、`list_snapshots`、`search`、`load_skill`。子 Agent 拥有独立 SQLite 会话，使用父会话的模型配置。父会话记录 `subagent_started` 和 `subagent_finished`；`subagent_status({ id })` 返回原任务的持久结果，子会话被删除或后续独立聊天不会替换已经保存的回答。

`spawn_subagent({ prompt, mode: "worktree" })` 启动可写子任务，自动为每个子任务创建独立的 `BRUIN_HOME/worktrees/agent-*` 分离工作树。它从父仓库 HEAD 开始，**不包含父工作区未提交改动**；父会话位于仓库子目录时，子任务仍被限制在对应子目录。不能指定或复用已有工作树。文件写入必须继承本段父任务的文件写入授权，或既有的全局自动审批配置；单次批准启动子 Agent 不等于自动授予全部工具权限。桌面手动入口提供单独的子任务文件写入授权勾选项。

启动时先固定 HEAD 对应的提交，再检查该提交中是否存在父会话的子目录。目录仅存在于未提交改动中时，Bruin 会在创建工作树前报错。创建完成后若无法登记任务，错误会给出已保留的工作树路径。

可写子任务在只读工具外仅增加 `write_file`、`edit_file` 和 `shell`。Shell 只允许启动时父会话/工作区已有的完整命令授权，以及父配置已启用的固定只读白名单；**必须使用现有 Shell 沙箱**，缺少沙箱时拒绝执行，不回退到宿主 Shell。不会继承任意命令自动执行、MCP、Hook、后台任务或嵌套 Agent 权限。文件工具禁止修改 `.git` 元数据。子任务使用父运行的模型调用预算与剩余时间预算；桌面手动启动默认 24 次调用和 30 分钟。父子预算分别计数，不是全团队统一 Token 或金额预算。

`subagent_status` 对可写任务补充工作区、起始提交、文件变更列表（最多 300 项）及审核错误。`subagent_review({ id, path })` 返回指定文件相对于起始提交的文本基线与当前内容。工作树后续提交后仍按起始提交审核；还原到该提交的文件会从变更清单移除。清单也包含未跟踪文件，Git 忽略的新增文件仅在有 Agent 写入记录时列出。两者只能查询当前父会话的子任务。`cancel_subagent({ id })` 取消本进程内运行的子任务，结算后释放父子租约。桌面「MCP 与自动化」提供模式选择、启动、状态、停止和单文件审核入口，运行中仍可查询和取消。

子任务停止运行后，在父会话的「MCP 与自动化」填写子 Agent ID，点击「导出子任务补丁」，选择新文件的保存位置。`.patch` 以子任务启动提交为基线，包含审核范围内的新增、修改与删除，支持二进制文件和符号链接。即使任务失败或取消，也可以导出保留的改动。遇到子模块、目录或补丁大于 10 MB 时会报告错误；保存会避免覆盖现有文件。补丁可在同一基线的干净 Git 工作树运行 `git apply --check` 验证。

在同一面板的「子任务联合预检」中，选择父会话当前仓库里使用相同启动提交的 2 至 10 个子任务，再点击「联合预检」。Bruin 在临时 Git 工作树中按选择顺序应用补丁，报告是否能一起应用、出现冲突的子任务和文件。任务完成后可用「刷新子任务」更新列表。写回父工作区需另行确认。

也可以输入命令并点击「预检并测试」。在系统对话框确认命令后，只有全部补丁应用成功才会在临时仓库根目录执行测试。测试通过现有 Shell 沙箱运行，宿主可写范围限于本次临时工作树。界面分别显示补丁结果、测试退出码和输出。测试最多运行两分钟。临时工作树取自启动提交，运行依赖需由提交内容或现有沙箱环境提供。

预检使用选中的共同基线，结果会显示提交 ID。同名文件与目录相撞时会列出阻止应用的路径。若预检期间切换父会话的工作区，请在当前工作区重新预检。

工作树和未提交改动在完成、失败、取消后均保留，**不自动提交、应用或合并**；合并需要用户另行确认。可在子会话中查看文件，或根据 `subagent_status` 返回的路径人工审查与集成。预检发现的冲突需要人工处理。运行中的工作树不能通过 `remove_worktree` 移除。关闭后台时取消正在启动和执行的子任务；重启后未完成任务显示为未知，必须由用户决定是否重新发起。Shell 隔离仍受现有平台沙箱的临时目录权限和文件系统竞争边界限制，不代表可安全运行敌对代码。

子 Agent 达到预算暂停、缺少正常结束事件，或取消后晚到返回时，父会话报告 `failed` 并说明原因。已经记录的失败原因可在后台重建后查询。结算前重新验证父子会话租约。租约失效或写入父会话结果失败时，原始子会话记录保留供后续恢复。对未结算的子任务，只有持有该任务的进程能发出取消信号，其他进程会明确报错；已结算的任务直接返回持久状态。后台 Shell 的取消状态也不会被晚到的成功或错误返回覆盖。

恢复扫描可以补齐「子会话已结束、父会话尚未保存结果」的记录：仅检查已失去租约的子会话，要求原始用户输入匹配委派提示词，并只采用第二条用户消息之前的首轮结束或暂停记录。原始回答会与结束事件序号一起记入父会话，重复恢复不会重复追加；后续独立聊天和预算报告不会替换原任务结果。恢复不执行模型或工具。没有可靠结束记录、原始输入不匹配或已删除的子任务保持未结算，主 Agent 会收到任务 ID 与工作区提示，回合结束时也会提示仍未记录结果的数量；不能将对话回合结束视为这些任务已经完成。

桌面手动启动和模型委派都会关联启动工具事件与对应子任务。若中断前已登记子任务，恢复会补齐该次启动回执。缺少可靠关联的启动仍需检查。桌面独立操作的回执可在会话中查看，主 Agent 通过子任务记录读取成果。

运行中的子 Agent 同时保留父会话和子会话的 SQLite 租约；后台 Shell 保留父会话租约。同一进程的前台回合和后台工作共享会话所有者，最后一项工作结算后才释放，因此主回合结束后仍可继续聊天，但不能在后台工作结算前删除会话或由其他进程接管。租约续期失败会向全部持有者发送取消信号；外部命令已经产生的副作用仍需人工检查。崩溃后沿用 30 秒租约过期机制，不自动重放后台工作。

## Git 工作树

`create_worktree` 从当前仓库 `HEAD` 创建分离工作树，目录位于 `BRUIN_HOME/worktrees/<name>`。名字只允许小写字母、数字和连字符。`list_worktrees` 查询 Git 的工作树列表。`remove_worktree` 只接受当前仓库中位于 Bruin 管理目录下的工作树，调用 `git worktree remove`，不会强制删除有未提交更改的工作树。创建和移除都需模型工具审批；桌面按钮代表用户直接发起操作。

只读子 Agent 可选择 Bruin 管理的工作树作为任务目录；可写子 Agent 总是创建自己的工作树。工作树不改变外部进程自身的权限，Bruin 的工具白名单、路径检查和 Shell 沙箱继续独立生效。

## 后台任务

`start_background(command)` 使用现有 `ProcessExecutor` 的 Shell 沙箱，在独立工具进程中启动命令，最多同时两个，10 分钟超时，输出最多 100 KB。通过 ID 查询或取消。启动前需模型工具审批；桌面按钮代表用户直接发起。事件日志记录开始和结束。应用重启后，不会自动重放未完成命令；状态显示为未知。取消会发送终止信号，但外部副作用无法回滚。

## Hooks

可配置 `turn_started`、`before_tool`、`after_tool`、`turn_finished` 四种 Hook。Hook 是用户保存的**静态 Shell 命令**，不把模型输出拼接进命令。通过与普通 Shell 相同的沙箱和 30 秒超时运行，结果写入 `hook_finished`。`turn_started` / `before_tool` 失败会中止当前执行；`after_tool` / `turn_finished` 的错误保留在事件中。未批准的规划阶段不运行 Hook，避免只读规划期间发生隐藏的修改。配置 Hook 等同于授权该静态命令在相应时机运行；启用前应检查命令。

执行器断线或抛出异常时，也会追加失败的 `hook_finished`，以 `executionUnknown` 标明未收到确定执行结果，然后继续向调用方传播异常；不会自动执行后续 Hook。成功的结束 Hook 不会改变主回合的完成状态。Cron 还会核对本次运行是否正常结算及是否出现 Hook 失败；异常或 Hook 结果无法保存时保持需要复核，不能仅凭较早的 `turn_completed` 报告成功。

## 完整规划模式

会话中点击「开启」后，规划状态作为 `plan_mode` 事件保存。模型可读取工作区并调用 `update_plan` 提交 1–30 个步骤；在用户批准前，写文件、Shell、MCP 调用、工作树变更、后台任务等均由权限层拒绝。计划显示在对话上方，用户点击「批准计划并允许执行」后写入 `plan_approved`，再发送“执行计划”等指令。执行中模型或用户可更新每一步的 `pending`、`in_progress`、`completed` 状态。修改计划会撤销原批准，需要重新审批。计划获批后，工具仍按审批规则执行；本段长任务可由用户额外授权工作区文件自动写入。

规划事件与其他会话事件一同恢复。规划模式是执行门禁与进度记录，不保证模型一定按计划实施，也不替代工具审批和操作系统沙箱。

模型结束当前回合时，如果获批计划仍有未标记完成的步骤，Bruin 会提示剩余步骤数量。回合结束仍允许用户提问或补充信息，不自动把计划标记为完成。

## 恢复和限制

会话操作按 `tool_requested` → `tool_approved` → `tool_started` → `tool_finished` 记录。长任务模式在同一运行中允许最多 240 次模型调用；显式无人值守模式可选 480 次，未授权操作立即记为 `tool_denied`，每 24 次记录进度。可单独授权本段自动修改工作区文件。中断时无法确认外部副作用，恢复扫描会标记 `tool_unknown`，要求人工检查后继续。后台任务和子 Agent 的开始、结束也有单独事件；重启不自动继续这些进程。

取消信号会在模型返回、每个工具执行前和审批返回后检查；尚未开始的同批调用记为 `tool_denied`，避免继续写入及错误地报告未知结果。已开始执行的操作仍按原有恢复机制处理，取消不会回滚外部副作用。

主模型请求由 `AgentRunner` 统一重试，最多三次尝试；已向用户输出部分正文的请求不重试。历史摘要调用独立保留一次 SDK 重试。当前轮次最近 200 条事件中，相同工具与参数累计失败或被拒绝三次会提示模型调整方法；相同请求成功、新用户输入和回合完成会重置相应计数。后台及子 Agent 状态轮询不计入。提示不自动暂停或提高权限。

当前已有跨进程会话租约和 Electron `safeStorage` 密钥加密。仍缺少 OAuth 凭证跨重启安全持久化、后台任务跨重启续跑、崩溃后 Docker 容器回收保证，以及面向敌对代码的强隔离。参见 [安全模型](SECURITY.md)、[生产化审查](PRODUCTION_REVIEW.md)与[机制对比](AGENT_COMPARISON.md)。

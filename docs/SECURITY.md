# 安全模型与运行限制

## 信任边界

用户输入、模型输出、工具输出、仓库文件、市场索引以及 `SKILL.md` 都可能包含不可信内容。Agent 的系统提示提醒模型不要把这些内容当成更高权限指令；真正的权限由主进程 `decisionFor` 与人工确认执行。任何提示词约束都不能代替操作系统隔离。

主进程持有模型 API 密钥；工具子进程仅继承最小环境变量。工具进程通过 IPC 接收限定格式请求，模型没有直接创建任意工具的能力。所有工具调用仍在主进程记录与授权后才发送。会话事件中的工具输出可能包含秘密；应保护 `BRUIN_HOME` 的访问权限、备份和终端日志。

## 工具权限

| 工具                                       | 默认权限 | 限制                                                        |
| ------------------------------------------ | -------- | ----------------------------------------------------------- |
| `read_file`                                | 自动允许 | 必须在工作区内；拒绝路径中的符号链接                        |
| `search`                                   | 自动允许 | 在工作区运行 `rg`，输出有字节上限                           |
| `load_skill`                               | 自动允许 | 仅能加载已启用 Skill；正文随会话记录                        |
| `write_file`、`edit_file`                  | 每次询问 | 限定工作区路径；覆盖和编辑会产生副作用                      |
| `shell`                                    | 每次询问 | 超时、输出限额；需配置可用的执行沙箱                        |
| `mcp_call`                                 | 每次询问 | 外部服务器可能读写数据或产生副作用                          |
| 工作树创建/移除、后台 Shell、子 Agent 启动 | 每次询问 | 由桌面直接点击发起时视作用户操作；后台 Shell 仍使用执行沙箱 |
| 状态查询、计划更新                         | 自动允许 | 计划未批准时禁止有副作用的工具                              |

用户在授权提示中应检查完整参数。批准 Shell 意味着允许命令在指定工作区内修改文件；Docker 模式下工作区以可写卷挂载。文件写入前会复核父目录与目标文件身份，但跨平台本地文件工具仍无法把路径检查和写入合成原子操作；其他进程并发替换符号链接时仍有竞态，不应视为针对恶意本地用户的强隔离文件系统。

## Shell 执行模式

### macOS 默认模式

Bruin 使用 `/usr/bin/sandbox-exec`，配置为拒绝网络与工作区、临时目录以外的文件写入。它仍允许读取工作区以外的文件，也没有完整限制进程与设备访问。macOS 上的 `sandbox-exec` 可用性和实际策略应在目标系统验收。此模式适合受信任开发机上的辅助防护，**不满足多租户或敌对代码运行的强隔离要求**。

### Linux 模式（优先 bwrap 轻量内核沙箱）

在 Linux 上，Bruin 会优先探测并启用 `bwrap` (Bubblewrap)。当前配置使用挂载和网络命名空间：工作区与系统临时目录可写，其他主机路径只读，Shell 无网络；它没有启用 PID 命名空间，也仍可读取工作区外可访问的文件。`bwrap` 无需后台守护进程，但启动仍有开销，且必须在目标系统验证。
若系统未安装或无法运行 `bwrap` 且未配置 Docker，模型提出的 Shell 命令在逐次人工批准后使用宿主 `/bin/sh` 执行。此时审批不提供操作系统隔离。
若需强制在缺少内核沙箱时硬报错拒绝，可配置 `BRUIN_ENFORCE_SANDBOX=1`。

### Windows 模式

在 Windows 上，模型提出的 Shell 命令经逐次人工审批后通过宿主 `cmd.exe` 执行；这不是沙箱隔离。若需强沙箱隔离，可配置 Docker 模式。

### Docker 模式

```sh
export BRUIN_SHELL_BACKEND=docker
export BRUIN_DOCKER_IMAGE=alpine:3.20
node dist/cli.js chat --workspace /path/to/project
```

容器使用 `--network none`、只读根文件系统、移除 capabilities、`no-new-privileges`、PID/内存限制、受限 `/tmp`，并将工作区挂载到 `/workspace` 可写。镜像必须预先存在；不要把主机 Docker socket 挂载进容器。每次运行使用唯一容器名；取消、超时和正常关闭执行进程时会尝试 `docker rm -f` 并在清理无法确认时报告错误。进程被直接强杀、系统崩溃或 Docker daemon 不可用时仍可能留下容器，需要外部巡检与目标平台验收。

## MCP、Hook 与编排边界

MCP stdio 服务器是用户配置的外部可执行程序。macOS 上使用 `sandbox-exec` 限制写入；Linux 有可用 `bwrap` 时限制写入，但当前 MCP 配置未隔离网络。Windows 或缺少沙箱时直接运行。Bruin 只传基础环境和显式列出的环境变量；**不受沙箱约束的服务器仍拥有运行账户的本机权限，且可在工具调用之间继续运行**。模型发起的 MCP 工具请求逐次审批，审批不能限制已启动服务器自身的行为。HTTP MCP 服务器可能访问外部系统；调用结果为不可信内容。远端 URL 要求 HTTPS，本机 loopback 可用 HTTP。当前不支持交互式 OAuth 授权。

Hook 是静态 Shell 命令，用户启用后按配置时机运行，不逐次弹窗；因此 Hook 必须使用可用的 Shell 沙箱，缺少沙箱时拒绝执行。规划模式未获批准时不运行 Hook。后台 Shell 由模型提出时需要审批，之后复用 Shell 执行模式；重启不保证继续执行，也无法撤销已产生的副作用。只读子 Agent 通过工具白名单限制；这不构成操作系统级进程隔离。

工作树使用 `git worktree add --detach` 与不带 `--force` 的 `git worktree remove`；移除仅限 Bruin 管理目录下当前仓库的工作树。模型启动和移除都需审批；桌面直接操作由用户本人发起。

## Skills 与供应链

远程 Skill 安装后默认停用，用户可以查看 `SKILL.md` 与快照文件后启用。安装从 GitHub 仓库取文件快照，不执行 Skill 自带安装脚本；但 Skill 指令可诱导模型提议危险工具调用，因此每次 Shell/写入仍需审批。更新远程 Skill 会重新停用，需要复审。当前无签名校验、依赖锁定或恶意脚本扫描。不要把未知来源的 Skill 当成可信代码。

## 需要补强后才能作严格生产承诺

1. Shell 容器异常崩溃后的孤儿容器巡检与资源回收；对 Docker daemon 操作设置独立最低权限。
2. 文件工具使用内核级目录句柄和 `openat` 类操作消除路径检查到使用之间的竞态，或在强制沙箱中运行全部工具。
3. 设计可审计的权限持久策略、审批身份与超时，避免终端共享场景下误授权。
4. 加密或访问控制事件数据，并规定保留、清理与备份恢复流程。
5. 对支持的操作系统、Provider、模型与故障注入场景完成端到端验收。

这些是明确的当前边界；本项目已实现基础机制，但不应宣称达到了跨平台、对敌对代码安全的生产隔离等级。

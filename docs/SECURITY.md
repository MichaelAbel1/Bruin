# 安全模型与运行限制

## 信任边界

用户输入、模型输出、工具输出、仓库文件、市场索引以及 `SKILL.md` 都可能包含不可信内容。Agent 的系统提示提醒模型不要把这些内容当成更高权限指令；真正的权限由主进程 `decisionFor` 与人工确认执行。任何提示词约束都不能代替操作系统隔离。

主进程持有模型 API 密钥；工具子进程仅继承最小环境变量。工具进程通过 IPC 接收限定格式请求，模型没有直接创建任意工具的能力。所有工具调用仍在主进程记录与授权后才发送。会话事件中的工具输出可能包含秘密；应保护 `BRUIN_HOME` 的访问权限、备份和终端日志。

## 工具权限

| 工具                                       | 默认权限 | 限制                                                        |
| ------------------------------------------ | -------- | ----------------------------------------------------------- |
| `read_file`                                | 自动允许 | 必须在工作区内；拒绝路径中的符号链接                        |
| `search`                                   | 自动允许 | 在工作区运行 `rg`，输出有字节上限                           |
| `load_skill`                               | 自动允许 | 仅能加载已启用 Skill；正文随会话记录                        |
| `write_file`、`edit_file`                  | 每次询问 | 限定工作区路径；覆盖和编辑会产生副作用                      |
| `shell`                                    | 每次询问 | 超时、输出限额；需配置可用的执行沙箱                        |
| `mcp_call`                                 | 每次询问 | 外部服务器可能读写数据或产生副作用                          |
| 工作树创建/移除、后台 Shell、子 Agent 启动 | 每次询问 | 由桌面直接点击发起时视作用户操作；后台 Shell 仍使用执行沙箱 |
| 状态查询、计划更新                         | 自动允许 | 计划未批准时禁止有副作用的工具                              |

用户在授权提示中应检查完整参数。批准 Shell 意味着允许命令在指定工作区内修改文件；Docker 模式下工作区以可写卷挂载。工具路径检查存在并发路径替换风险，尤其当其他进程同时修改工作区符号链接时；当前实现不应视为针对恶意本地用户的强隔离文件系统。

## Shell 执行模式

### macOS 默认模式

Bruin 使用 `/usr/bin/sandbox-exec`，配置为拒绝网络与工作区、临时目录以外的文件写入。它仍允许读取工作区以外的文件，也没有完整限制进程与设备访问。macOS 上的 `sandbox-exec` 可用性和实际策略应在目标系统验收。此模式适合受信任开发机上的辅助防护，**不满足多租户或敌对代码运行的强隔离要求**。

### Docker 模式

```sh
export BRUIN_SHELL_BACKEND=docker
export BRUIN_DOCKER_IMAGE=alpine:3.20
node dist/cli.js chat --workspace /path/to/project
```

容器使用 `--network none`、只读根文件系统、移除 capabilities、`no-new-privileges`、PID/内存限制、受限 `/tmp`，并将工作区挂载到 `/workspace` 可写。镜像必须预先存在；不要把主机 Docker socket 挂载进容器。当前工具超时会杀死 `docker run` 客户端进程，但未建立容器 ID 跟踪与取消后强制清理保证；在承载不可信代码前必须补齐并验收这一点。Docker daemon 不可用时 Shell 调用会失败。

### 显式无沙箱模式

`BRUIN_ALLOW_UNSANDBOXED_SHELL=1` 可让 Shell 直接在主机运行，适用于受控测试环境。它跳过 Shell 操作系统隔离，不能作为默认生产配置。设置 `BRUIN_SHELL_BACKEND=docker` 时优先使用 Docker。

Linux/Windows 若没有 Docker 配置，Bruin 默认拒绝 Shell；文件工具仍由独立 Node 子进程执行。**独立进程本身不是安全沙箱**，无法替代容器、受限系统用户或操作系统强制访问控制。

## MCP、Hook 与编排边界

MCP stdio 服务器是用户配置的外部可执行程序。Bruin 只传基础环境和显式列出的环境变量，但**目前没有把 MCP 服务器放进文件工具或 Shell 沙箱**；服务器本身拥有运行账户可访问的本机权限。HTTP MCP 服务器可能访问外部系统；调用结果为不可信内容，工具调用需要逐次审批。远端 URL 要求 HTTPS，本机 loopback 可用 HTTP。当前不支持交互式 OAuth 授权。

Hook 是静态 Shell 命令，用户启用后按配置时机运行，不逐次弹窗；它复用 Shell 沙箱。规划模式未获批准时不运行 Hook。后台 Shell 同样复用 Shell 沙箱，但重启不保证继续执行，也无法撤销已产生的副作用。只读子 Agent 通过工具白名单限制；这不构成操作系统级进程隔离。

工作树使用 `git worktree add --detach` 与不带 `--force` 的 `git worktree remove`；移除仅限 Bruin 管理目录下当前仓库的工作树。模型启动和移除都需审批；桌面直接操作由用户本人发起。

## Skills 与供应链

远程 Skill 安装后默认停用，用户可以查看 `SKILL.md` 与快照文件后启用。安装从 GitHub 仓库取文件快照，不执行 Skill 自带安装脚本；但 Skill 指令可诱导模型提议危险工具调用，因此每次 Shell/写入仍需审批。更新远程 Skill 会重新停用，需要复审。当前无签名校验、依赖锁定或恶意脚本扫描。不要把未知来源的 Skill 当成可信代码。

## 需要补强后才能作严格生产承诺

1. Shell 容器取消后强制清理并验证资源回收；对 Docker daemon 操作设置独立最低权限。
2. 文件工具使用内核级目录句柄和 `openat` 类操作消除路径检查到使用之间的竞态，或在强制沙箱中运行全部工具。
3. 设计可审计的权限持久策略、审批身份与超时，避免终端共享场景下误授权。
4. 加密或访问控制事件数据，并规定保留、清理与备份恢复流程。
5. 对支持的操作系统、Provider、模型与故障注入场景完成端到端验收。

这些是明确的当前边界；本项目已实现基础机制，但不应宣称达到了跨平台、对敌对代码安全的生产隔离等级。

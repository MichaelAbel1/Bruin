# 本机后台服务

构建后运行 `node dist/cli.js service run --timezone Asia/Shanghai`，无需 Electron 或桌面窗口。此命令以前台常驻进程运行，可由操作系统服务管理器或终端后台运行机制托管；Ctrl+C/SIGTERM 会取消在途执行并释放资源。不自动安装开机服务，不监听 HTTP/TCP 端口，不提供远程访问。

服务复用桌面后台的模型、工具、Cron 和任务图运行时，输出 JSON Lines 运行事件。`BRUIN_HOME` 与桌面保持一致即可使用同一数据库，跨进程租约阻止同一会话同时执行。服务通过环境变量获取模型密钥，不能解密 Electron 系统加密存储中的密钥。服务内自动任务使用无人值守策略，未预先授权的操作立即拒绝，不等待不存在的审批界面。

Cron 仍是五段表达式，使用进程时区；`--timezone` 接受 IANA 时区名。创建任务与执行服务应使用相同时区，现有任务的首个已保存时间点不会因切换时区重写。服务每 15 秒检查一次，忙时等待；错过多个时间点仅执行一次，再计算下一次时间，不逐个补跑。

每次派发与 `cron_started` 事件在同一 SQLite 事务提交，记录 runId、jobId、预定时间与时区；结束通过 `cron_finished` 记录状态。未结算执行在失去租约且派发超过 30 秒后标为 `needs_review`，阻止后续自动调度，且不会重放副作用。查看 `node dist/cli.js cron list` 和 `sessions show SESSION_ID`，检查工作区及工具事件后，用 `cron review JOB_ID --confirm` 解锁后续到期执行。尚无逐任务时区或暂停/启用界面。

同一会话已有派发记录时，其他到期作业保留原预定时间，等该记录结算后再竞争。调度器持有会话租约直到写入本次结果，随后进入的新回合不会干扰结算。若结算前失去租约，中断恢复会在取得租约后再次核对派发记录，只将扫描到的那一轮标记为待复核。其他进程已取得租约的会话留待后续检查。

正常结算按本次运行的回合状态与执行结果判断，成功的结束 Hook 或晚到后台事件不会将成功任务误标为失败；历史 Hook 失败也不会污染新运行。本次发生 Hook 失败、执行器异常或结果记录失败时仍标为 `needs_review`，即使模型已提前写下 `turn_completed`，也不能据此宣告整个调度运行成功。

在桌面添加定时任务时，可勾选关联当前已批准的计划版本。作业按该版本的累计进度结算。如果还有未完成步骤，作业进入 `needs_review`，原因保存在 `cron_finished` 事件。版本被替换、停用或尚未获准时，作业会在调用模型前进入待复核。普通定时任务按本次运行与 Hook 结果结算。需要使用新计划版本时，可创建关联新版本的作业。

每次启动任务前仍核对未结算工具调用。Cron 显式确认写入 `cron_reviewed`，仅确认截至当时的未知结果序号；后来出现的未知结果仍会阻止执行。确认不会补跑旧工具或绕过新工具审批。

如果确认命令的恢复扫描新发现未知结果，命令会先保存这些结果并退出。查看更新后的事件并检查工作区后，可再次确认。

## 任务图自动调度

任务在回合启动前失败时会释放认领，之后的调度检查可以再次认领。回合已启动但结算写入失败时，调度器保留已写入的状态并停止续约。尚未结算的任务在租约到期后的认领检查中标为 `unknown`。请先检查运行结果，再决定是否手动重试。依赖任务仅在前置任务为 `completed` 时可以启动。

认领以 SQLite 中的租约为准。同步工作区快照后，只有仍由本进程持有且未过期的任务才能启动。快照写入失败时，数据库中已保存的状态仍然有效。目录恢复可写后，可通过桌面修复入口重新同步。

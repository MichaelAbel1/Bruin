本次检查基于当前工作区源码、现有测试和下列官方资料，比较 Claude Code、Gemini CLI、Cursor、Aider 的机制。未执行产品间效果或速度基准；下表是能力与实现风险比较，不是性能排名。工作区原有未提交的长任务与无人值守改动已保留。

## 已落地的边界

改动集中在 `src/core/history.ts`，复用既有提示词预算、消息重建与事件存储，不增加依赖。工具结果缩减保留调用 ID 与结果配对；需要把当前轮次活动整体折叠时，同时移除调用和结果，生成标明不可信记录的摘要。原始事件与工具输出仍保留在 SQLite。

当前请求过长时仍可能被现有模型摘要或首尾摘录压缩；中间细节不能保证无损。窗口预算仍按 UTF-8 字节估算，未计入提供商序列化后的工具 schema 等全部开销，因此仍可能触发 Provider 的上下文错误。此次改进针对请求误丢失、系统指令截断、工具尾部状态遗漏和模型切换边界丢失。

系统指令或图片超过预算时，现在停止并提示增大窗口或减少输入。该行为优先保留必要信息；过小窗口可能比以前更早报错。

## 第三轮：文件完整性与连接隔离

继续对照上述文件工具、项目记忆和 MCP 资料，复查前两轮留下的边界。本轮未新增工具或修改数据库结构。

| 机制           | 新发现的痛点                                                                                                  | 改进与边界                                                                                                                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 桌面文件编辑   | `readWorkspaceFile` 只读前 256 KB，编辑器仍允许将该片段保存为完整文件，可能丢失剩余内容                       | 截断预览设为只读，保存按钮和快捷键拒绝保存；写入端拒绝覆盖超过预览上限的现有文件，也覆盖“读取后文件变大”的情况。大文件请用外部编辑器                                                                 |
| UTF-8 文件读取 | 工具与桌面预览使用 Buffer.toString，截断多字节字符时会生成替换字符；错误编码也会悄悄混入模型或编辑内容        | 严格 UTF-8 解码；截断预览保留完整字符，非法编码明确拒绝。非 UTF-8 文件需要外部转换后读取                                                                                                             |
| 项目指令       | fstat 后读取整个指令文件，无法再次限制文件增长；无效 UTF-8 指令被替换字符掩盖                                 | 实际读取最多 32001 字节，再检查 32000 字节边界；严格解码，拒绝损坏的指令文本                                                                                                                         |
| MCP 并发与恢复 | 旧代码只排队连接阶段；A 工作区的调用未完成时，B 工作区的连接可关闭 A 的客户端；手动 disconnect 也可能中断请求 | 同名服务整个操作串行，切换、断开与关闭等待活动请求；失败不阻塞后续队列。不同服务互不排队，同名服务的慢请求会增加排队等待                                                                             |
| Skills 与压缩  | skill_loaded 事件保存了版本，但模型摘要可能遗漏 Skill 工作流，后续提示词没有提示恢复                          | 加入最近最多 50 个已加载 Skill 快照的名字，提示相关时通过原有 load_skill 恢复原版本。没有自动扩大权限或重新注入全部 Skill 正文                                                                       |
| MCP 分页       | 复查 tools/list 是否只取第一页                                                                                | 当前 SDK 2.1 已自动合并分页，复用现有实现，未重复编写分页逻辑。参见 [MCP 分页规范](https://modelcontextprotocol.io/specification/2025-11-25/server/utilities/pagination)及本地 SDK 的 listTools 实现 |
| 仓库探索与成本 | 文件分页、目录发现仍不足；usage 保存在事件中但没有费用上限；任务恢复继续依赖事件与人工复核                    | read_file 可选分页与只读 list_files 扩展已提出确认，尚未实施。符号索引、金额预算、文件快照和后台续跑仍待设计                                                                                         |

新增 6 项回归测试，覆盖字符截断与损坏编码、大文件尾部保留、读取后文件增大、指令限制、MCP 工作区切换/断开/关闭/失败后继续，以及压缩后的 Skill 恢复提示。全量测试在现有桌面依赖的隔离环境中执行：123 项中 122 项通过、1 项因平台条件跳过；核心和桌面类型检查、构建通过。

未验证真实 Provider、真实远端 MCP 或桌面点击流程。大文件禁止覆盖保护不等于全面并发编辑保护：小文件在浏览后被其他进程修改，仍需要带原始版本校验的保存契约；新增该契约需要单独确认。权限模式、跨机器协作、OAuth、成本上限和签名发布的既有差距继续保留。

# Agent 机制检查与改进（2026-09-30）

本次检查基于当前工作区源码、现有测试和下列官方资料，比较 Claude Code、Gemini CLI、Cursor、Aider 的机制。未执行产品间效果或速度基准；下表是能力与实现风险比较，不是性能排名。工作区原有未提交的长任务与无人值守改动已保留。

## 已落地的边界

改动集中在 `src/core/history.ts`，复用既有提示词预算、消息重建与事件存储，不增加依赖。工具结果缩减保留调用 ID 与结果配对；需要把当前轮次活动整体折叠时，同时移除调用和结果，生成标明不可信记录的摘要。原始事件与工具输出仍保留在 SQLite。

当前请求过长时仍可能被现有模型摘要或首尾摘录压缩；中间细节不能保证无损。窗口预算仍按 UTF-8 字节估算，未计入提供商序列化后的工具 schema 等全部开销，因此仍可能触发 Provider 的上下文错误。此次改进针对请求误丢失、系统指令截断、工具尾部状态遗漏和模型切换边界丢失。

系统指令或图片超过预算时，现在停止并提示增大窗口或减少输入。该行为优先保留必要信息；过小窗口可能比以前更早报错。

## 验证

- `npm run check`、`npm run build`、`npm run desktop:check` 通过。
- 修改文件的 Prettier 检查通过。
- 新增 `src/tests/history.test.ts`：5 项回归测试通过，包含长单轮、重试预算、工具协议、中文文本、图片、指令完整性、模型切换和输出末尾失败信息。
- 现有上下文相关测试 7 项通过；旧测试关于截断系统指令的断言改为验证明确拒绝，其他断言保留。
- 全量测试在临时目录中使用项目已有 `.desktop-runtime/node_modules`：100 项通过、1 项因平台条件跳过；此后新增的输出末尾回归测试也通过。

直接 `npm test` 受到环境限制：根目录 better-sqlite3 为 Node ABI 115，而当前 Node 为 ABI 127；沙箱也限制本机端口监听。隔离验证复用了已存在且 ABI 匹配的桌面依赖，并允许本地测试端口，没有重装或修改项目依赖。未执行真实 Provider 或桌面端到端验收。

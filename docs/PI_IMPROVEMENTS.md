# Pi 架构借鉴与分步优化

每一步独立验证、提交和推送；继续复用 AI SDK、SQLite 事件与现有执行器。

## 第一步：上下文预算与长单轮压缩

- 预算改用估算 token，区分 ASCII、非 ASCII 和图片；保留 25% 窗口余量，并计入工具定义和协议开销。
- 同一运行内用 Provider 实际输入用量向上校准估算比例；不跨模型复用，也不因低用量报告降低保守估算。
- 单个用户请求包含多次模型调用时，可在已结算工具之后压缩前缀，保留最近两个模型响应；原始目标与附件单独保留，原始事件保留。
- Provider 上下文超限时，重试预算同时参考实际发送内容，确保缩减目标小于失败请求，而非仅缩小配置窗口。

估算仍不是精确 tokenizer。图片按固定开销计入，模型摘要仍有损；系统指令和图片超过预算时明确报错。现有 32,768 token 配置不再表示约 24 KB 文本上限。

验证：核心与桌面 TypeScript 检查通过；上下文及 Agent 控制回归测试通过。首次全量测试 192 通过、9 失败、1 平台条件跳过；9 个失败均为本机 HTTP 连接的环境错误（EADDRNOTAVAIL），无端口的核心测试通过。完整验收仍需 GitHub CI 与真实模型测试。

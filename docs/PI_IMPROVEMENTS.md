# Pi 架构借鉴与分步优化

每一步独立验证、提交和推送；继续复用 AI SDK、SQLite 事件与现有执行器。

## 第一步：上下文预算与长单轮压缩

- 预算改用估算 token，区分 ASCII、非 ASCII 和图片；保留 25% 窗口余量，并计入工具定义和协议开销。
- 同一运行内用 Provider 实际输入用量向上校准估算比例；不跨模型复用，也不因低用量报告降低保守估算。
- 单个用户请求包含多次模型调用时，可在已结算工具之后压缩前缀，保留最近两个模型响应；原始目标与附件单独保留，原始事件保留。
- Provider 上下文超限时，重试预算同时参考实际发送内容，确保缩减目标小于失败请求，而非仅缩小配置窗口。

估算仍不是精确 tokenizer。图片按固定开销计入，模型摘要仍有损；系统指令和图片超过预算时明确报错。现有 32,768 token 配置不再表示约 24 KB 文本上限。

验证：核心与桌面 TypeScript 检查通过；上下文及 Agent 控制回归测试通过。首次全量测试 192 通过、9 失败、1 平台条件跳过；9 个失败均为本机 HTTP 连接的环境错误（EADDRNOTAVAIL），无端口的核心测试通过。完整验收仍需 GitHub CI 与真实模型测试。

## 第二步：内部工具注册表

将工具 schema、模型可见范围、执行位置、规划模式可用性、只读与后续并发/恢复分类集中在 `src/core/tools.ts`。Provider、Runner 和规划门禁读取同一注册表；原有 `gateway.toolSchemas` 导出保持兼容。路径验证、审批与执行器复核继续独立执行，注册不会授权。

验证覆盖 basic/full/read-only 模式工具集合、规划门禁、未知及原型属性工具名拒绝，以及既有核心/执行控制回归。

## 第三步：持久化输入队列

桌面运行时可选择「补充当前任务」或「当前任务结束后」发送。前者在下一次模型调用前处理，后者在模型给出无工具调用的回答后处理；均不会中断或重放已开始的工具。队列不扩大权限、调用次数或时间预算。

`input_queued` 保存原始消息、引用和附件；真正进入上下文时追加带队列 ID 的 `user` 事件，该事件同时作为持久确认，避免分开确认造成崩溃丢消息。最多 50 条待处理消息。停止、预算耗尽或重启后保留消息，需继续任务处理；不自动跨会话运行。

验证：持久化重开与去重、工具/回答边界顺序、预算耗尽暂停、既有 Agent 控制回归和桌面类型检查。

## 第四步：受控只读并发

仅当整批工具都在注册表中明确允许并发、且没有启用工具前后 Hook 时，最多并发执行三个工具。包含写入、Shell、MCP 或状态修改的混合批次继续串行。同步文件读取仍受单个 worker 的事件循环限制，异步搜索等操作可以重叠；未承诺所有读文件场景都会加速。

实际完成事件按完成顺序记录；构建模型上下文时按模型原始调用顺序排列工具结果。失败或取消后停止派发、等待已开始的工具结算，再拒绝未开始的调用，避免下轮模型与上一批工具交错。

验证：并发上限、乱序完成时的上下文顺序、失败等待与未执行调用拒绝，以及既有写入取消回归。

## 第五步：中断恢复分类

没有 `tool_started` 的请求记为未执行拒绝；明确标记安全且未带工具 Hook 的执行器只读调用记为失败结果。已开始的写入、Shell、MCP、运行时工具，以及缺少安全标记的旧记录仍记为 `tool_unknown`，保持人工检查。恢复只补齐结果，绝不自动重放。

工具开始事件保存恢复分类；整批工具使用同一份 Hook 配置快照，避免执行中变更配置让只读调用意外运行有副作用的 Hook。配置更新在下一批生效。现有未知事件不会被重新解释或取消复核。

验证覆盖数据库重开、恢复幂等、未开始的写入、安全读取、旧版读取、Hook 读取、错误安全标记的写入、Shell 和执行异常。

## 第六步：桌面展示模块拆分

从主入口提取 `files/FileEditorViewer.tsx`、`files/line-diff.ts`、`conversation/Messages.tsx`、`conversation/events.ts` 和日期格式化函数。组件由属性传递状态与回调，不依赖主入口；附件类型复用核心定义。差异算法、语法高亮、Markdown 安全选项及消息分组规则原样迁移。

验证：提取前后的实现正文比对一致；桌面类型检查与生产构建。会话分支及其文件/工作树恢复语义尚未实现，后续应单独设计和验收。

# Bruin 对照 12-Factor Agents 的评估与改进记录

基线评估始于 2026-11-19（Bruin 0.12.1），最近一次能力补齐与复核更新于 2026-11-25（Bruin 1.1.1）。本文面向本机编码助手的 CLI、桌面、IDE 和后台调度场景。[12-Factor Agents 原文](https://github.com/humanlayer/12-factor-agents)

**对照 12 项原则，核心能力均已落地**：在原有提示词/上下文/工具分派与长任务基础上，进一步补齐了统一无状态会话归约器、结构化 `ask_user`（选项/背景/类型与交互式 CLI/桌面/ACP 展示）、错误输出 ANSI 清洗与重复行折叠、确定性重复失败熔断与只读空转纠偏、微代理作用域/交付物/步数上限约束、`sessions status` 与 `chat --json` 自动化接口，以及可选 HTTPS/本机 Webhook 人工注意通知。

## 建议实施顺序

下列顺序针对本次评估发现的缺口。项目整体排期、优先级含义和相关任务编号见[现有改进路线图](IMPROVEMENT_ROADMAP.md)。

### P1 · 让用户在重启后回答 Agent 的问题

**实施进展。** CLI 与桌面已实现每个会话一次一个待答问题。首次有效答复使用会话租约校验并写为用户事件，续跑从该事件读取问题和答复。[使用说明](LONG_TASKS.md) · [跨进程回归](../src/tests/desktop-queue.test.ts)

**场景。** 无人值守任务需要确认“这次迁移要兼容哪个旧版本”。当前用户可以在对话里回复，但调度器无法从记录判断这条消息回答了哪个待决问题，也无法将工作可靠地停在该处。现有普通工具审批会等待进程内回调，重启后会按恢复规则结算。[桌面审批](../src/desktop-host.ts) · [恢复规则](../src/core/recovery.ts)

**建议。** 先在 CLI 和桌面支持一问一答。Agent 发起提问时记录原会话、请求 ID 和问题，持久化等待状态后结束本段运行。用户在任一入口回答时，先核对请求归属，再复用事件存储、输入队列和会话租约接续。业务答复只补充任务信息；工具执行继续经过现有授权。实施前需确认新增工具与事件的兼容语义。[输入队列](../src/core/input-queue.ts) · [会话租约](../src/core/session-leases.ts)

**验收场景**

- 从桌面提出问题，退出进程，从 CLI 打开同一会话。原问题仍可见，回答后模型能收到问题和答案，已完成的工具调用不会被重放。
- CLI 和桌面同时答复同一请求，只有一个答案被采纳；在答案落盘后、再次调用模型前中断，恢复后答案仍只消费一次。
- 回答业务问题后，如下一步需要工具授权，仍显示原有审批；存在未经复核的未知副作用时，继续走现有复核流程。

### P1 · 让 Cron 的完成状态反映交办事项

**实施进展。** 创建作业时可显式关联已批准计划的版本。结算记录包含关联计划的未完成步骤。版本失效时，作业在模型调用前进入待复核。恢复也会复核派发事件序号，防止误结算并发派发的新一轮。[使用说明](SERVICE.md) · [调度回归](../src/tests/cron-service.test.ts)

**场景。** 已批准计划还有一步未完成时，Runner 会提示剩余步数，随后写入 `turn_completed`。Cron 结算检查运行是否正常返回、回合是否结束以及本次 Hook 是否失败。三者均满足时，即使用户交办的计划仍有缺项，也可能记录 `completed`。这是由代码路径识别出的风险，尚未作为独立场景复现。[回合收尾](../src/core/agent.ts) · [Cron 结算](../src/desktop-host.ts)

**建议。** 在路线图第 11 项“有执行证据的任务验收摘要”中补充 Cron 消费该结果的规则。保留普通对话的结束语义，先明确哪些计划或验收条件属于本次作业。结算时若仍有相关缺项，复用已有 `needs_review` 并记录具体原因。归属无法从现有事件可靠推导时，先确定关联方式，避免把同一会话中的历史计划算到新作业上。[计划投影](../src/runtime/plan.ts) · [调度回归](../src/tests/cron-service.test.ts)

| 验收情形                                                   | 预期结算                                            |
| ---------------------------------------------------------- | --------------------------------------------------- |
| 本次作业的已批准计划还有一项未完成，模型提前给出最终答复   | 对话可以结束；作业为 `needs_review`，可查到未完成项 |
| 本次计划已完成，运行正常，Hook 成功                        | 作业为 `completed`                                  |
| 本次为普通问答且正常完成，同一会话存在无关的历史未完成计划 | 仅按本次作业结算，历史计划不触发复核                |
| 本次 Hook 失败，或恢复发现未知副作用                       | 保留现有失败或复核路径；重复恢复不会补跑原工具      |

### P2 · 用只读审查检验子 Agent 的职责边界

先从一个可测的交付物入手。父 Agent 在现有委派提示中给出审查范围、问题和结束条件；子 Agent 返回发现、文件位置、验证依据和未检查范围。首轮可沿用现有工具参数和只读权限。与路线图第 06、29 项共用固定任务样本，积累数据后再决定是否投入第 30 项的可配置角色。[委派定义](../src/core/tools.ts) · [子任务运行器](../src/runtime/subagent.ts)

**验收。** 在相同仓库版本、模型、权限和预算下，分别运行自由文本委派与明确交付条件的委派。样本包含已知缺陷和无缺陷对照，记录命中、误报、漏报、模型调用数，以及父 Agent 能否根据返回的位置复核发现。保留两组原始结果，推广与否由实际质量和成本决定。

**实测。** 2026-11-23 使用本机 MLX 的 Qwen2.5-Coder-3B-Instruct 4-bit。只给委派提示时，两组均漏掉已知缺陷，每次各调用模型一次，均未读文件。提供相同源码后，两组各有两项无法按位置和反例复核的报告，各漏掉一处已知缺陷，其中无缺陷样本各产生一项误报。带行号快照的复跑计分相同。所有样本工作区保持干净。此次对照未观察到结构化提示提高可复核命中率。[评测入口](../test/evals/subagent-review.mjs) · [原始答复及计分](../test/evals/results/2026-11-23-subagent-review.json)

### P2 · 支持 IDE 断线后接回原会话

**实施进展。** 已支持 ACP v1 会话加载。在 macOS 的 Zed 1.29.3 退出并重开后，新 Bruin 进程使用同一会话 ID 重放首轮历史。续跑成功引用了先前的真实文件读取结果，SQLite 显示两轮完成且只执行一次读取。IDE 验证使用固定模型响应，重复加载、跨工作区拒绝及未知副作用拦截另由协议回归覆盖。[客户端与实测](ACP.md) · [协议回归](../src/tests/acp.test.ts)

沿用路线图第 28 项。先在一个实际支持 ACP 的 IDE 验证建会话、断线、重开、加载历史和继续工作。待答业务问题可在加载后重新展示；已失效的权限请求遵循现有恢复规则。验收覆盖旧客户端能力协商、重复重连、未知副作用待复核和历史工具结果不重放。远程消息渠道可在有具体用户场景时另行评估。[ACP 说明](ACP.md) · [协议测试](../src/tests/acp.test.ts)
